왜 이 세 가지인가

깊이가 장식이 아니라 정보가 되는 경우

높이를 값 하나에만 쓰는 2.5D 막대는 2D 막대보다 정확하지 않습니다. 이번 세 엘리먼트는 바닥의 위치나 위아래 순서 자체가 데이터인 경우만 다룹니다.

엘리먼트

세 엘리먼트 설계

<iso-map> 평면 배치

그리는 것
바닥 평면 위에 위치·크기가 제각각인 칸을 놓고, 값을 높이나 색으로 보여 줍니다.
데이터
{ "floor": {"w": 8, "d": 9}, "items": [{ "k": "7번", "x": 3, "y": 1.5, "w"?: 1, "d"?: 1, "v"?: 6, "state"?: "absent" }] }
핵심 동작
겹치지 않는 임의 크기 칸의 앞뒤 순서를 계산합니다. 칸이 겹치면 오류 상태입니다. state(결석·빈자리·공사 중)는 높이 0과 점선으로 구분합니다.
접근성
숨김 표에 칸 이름, 값, 위치(행·열)를 함께 넣습니다.
템플릿
교실 좌석표, 학교 평면도(층은 탭으로 전환)

<iso-layers> 층 구조

그리는 것
판을 위아래로 쌓고, 판마다 항목 블록을 올립니다. ledger와 달리 판 안에 내용이 있습니다.
데이터
[{ "k": "4학년", "items": [{ "k": "분수", "v": 72 }] }]
핵심 동작
open 속성으로 한 층을 펼치면 그 위 층들이 들려 올라가 항목이 가리지 않습니다. 위·아래 키로 층을, 좌·우 키로 항목을 이동합니다.
이벤트
iso-select의 detail은 { layer, index, item }입니다.
템플릿
성취기준 층 구조(학년 판 위에 단원 블록, 높이 = 평균 성취도)

<iso-city> 위계를 건물로

그리는 것
트리맵으로 바닥을 구역으로 나누고, 그 위에 건물을 세웁니다. 밑면은 size, 높이는 v입니다.
데이터
{ "k": "학교", "children": [{ "k": "1학년", "children": [{ "k": "1반", "size": 27, "v": 64 }] }] }
핵심 동작
squarified 트리맵으로 구역과 건물 밑면을 정하고, iso-map과 같은 깊이 정렬로 그립니다. 라벨이 많아지므로 구역 이름은 항상, 건물 이름은 호버·포커스 때만 보입니다.
성능
건물 300개 첫 렌더 100ms 이하(CPU 6× 감속)를 목표로 합니다. 200개를 넘으면 SVG 경로로 전환합니다.
템플릿
학교 도시(구역 = 학년, 건물 = 학급, 밑면 = 학생 수, 높이 = 독서량 같은 지표)
템플릿

교육용 템플릿 4종

모든 템플릿은 가상 데이터로 열리고, 교사가 자기 데이터(JSON)를 붙여 넣어 바로 바꿔 볼 수 있습니다.

템플릿엘리먼트화면예시 데이터
교실 좌석표iso-map좌석 20–30개, 교탁, 결석 표시. 좌석을 누르면 옆에 그 번호의 주간 기록이 나옴과제 제출 횟수, 발표 참여 횟수
학교 평면도iso-map층 탭(1–4층), 교실·특별실·복도 칸, 칸 크기가 실제 비율교실별 크롬북 사용 시간, 특별실 예약률
성취기준 층 구조iso-layers학년 판 4–6장, 판 위 단원 블록. 한 학년을 펼쳐 단원을 비교단원별 평균 성취도(%)
학교 도시iso-city학년 구역 6개, 학급 건물 20–30개밑면 = 학생 수, 높이 = 1인당 월 독서량
공통 기반

먼저 고정할 세 가지

  • 교육용 엔트리를 따로 낸다. 코어 JS가 4.68KB로 예산 5KB에 거의 닿아 있습니다. 세 엘리먼트는 2.5d-ui/edu(iso-edu.min.js)로 따로 빌드하고 공통 기반(base)은 공유 청크로 나눕니다. 예산은 코어 5KB를 그대로 두고 교육용 엔트리에 3KB(gzip)를 새로 둡니다.
  • 불규칙 배치 깊이 정렬(order.ts). 서로 겹치지 않는 축 정렬 칸은 "앞에 있다" 관계로 위상 정렬하면 순서가 정해집니다. 무작위 배치 1000건 속성 테스트로 앞뒤를 어기는 쌍이 0개인지 확인합니다. CSS 경로는 이 순서를 --iso-z로, SVG 경로는 DOM 순서로 씁니다.
  • 트리맵(treemap.ts). squarified 배치를 직접 구현합니다(의존성 없음). 면적 비례 오차 1% 이내, 평균 종횡비 3 이하를 테스트로 확인합니다.

학생 개인정보 원칙

  • 템플릿과 예제의 데이터는 모두 가상입니다. 학생은 번호로만 표시합니다.
  • 라이브러리는 데이터를 어디에도 보내지 않습니다. 화면에 그리는 것만 합니다. 이 점을 문서에 적습니다.
  • 숨김 접근성 표에도 화면과 같은 내용만 들어갑니다. 이름을 넣으면 스크린 리더가 읽는다는 점을 템플릿 안내에 적습니다.
  • 학사 시스템 연동이나 파일 가져오기는 이번 범위가 아닙니다.
일정

단계별 계획

하네스 계획서의 6단계입니다. 2–4단계와 5–6단계는 각각 같은 wave에서 병렬로 진행합니다. 기간은 이번 v0.1 진행 속도를 기준으로 한 추정치입니다.

  1. W1

    공통 기반 iso-edu-foundation

    단독 · 반나절

    교육용 엔트리 분리 빌드, order.ts, treemap.ts, 세 엘리먼트의 API 규격.

    AC코어 5KB·교육용 3KB 예산 강제 · 깊이 정렬 속성 테스트 1000건 위반 0 · 트리맵 면적 오차 1% 이내

  2. W2

    iso-map · iso-layers · iso-city

    병렬 3팀 · 하루

    각 엘리먼트, 데모, 단위·화면 테스트. 세 팀 모두 W1의 API 규격을 기준으로 합니다.

    AC크기가 섞인 평면도의 가림 정확 · 층 펼치기와 키보드 이동 · 건물 300개 첫 렌더 100ms 이하

  3. W3

    React 래퍼 · 템플릿과 문서

    병렬 2팀 · 반나절

    IsoMap, IsoLayers, IsoCity 추가. 문서 사이트에 엘리먼트 페이지 3개와 교육용 템플릿 4종.

    ACReact 18·19 통과 · 템플릿 콘솔 오류 0 · 390px 가로 스크롤 없음 · 예시 데이터는 모두 가상, 번호 표시

각 카드는 v0.1과 같은 방식으로 진행합니다. 작업 폴더에서 빌드하고, Codex 독립 리뷰를 통과하면 PR로 스쿼시 머지합니다.

위험과 대응

위험대응
크기가 다른 칸의 앞뒤 순서 오류위상 정렬과 속성 테스트, 겹치는 배치는 오류로 거부, 화면 기준 이미지로 확인
iso-city 라벨 겹침건물 이름은 호버·포커스 때만 표시, 구역 이름만 항상 표시, 모든 이름은 숨김 표에 포함
교육용 엔트리 크기 초과엔트리별 size-limit, 공유 청크로 base 중복 제거, 초과 시 기능을 줄이고 보고
iso-layers 펼침 애니메이션이 값 변경 애니메이션과 같은 한계에 걸림펼침은 판 위치(transform)만 움직여 컴포지터에서 처리, 측정 후 결과 보고
교육 데이터 개인정보가상 데이터와 번호 표시, 외부 전송 없음 명시, 템플릿 안내문
크롬북 실기기 미측정(v0.1부터 이어짐)W3 이후 실기기에서 템플릿 4종의 첫 렌더·호버 측정
